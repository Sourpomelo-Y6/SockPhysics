## 文書の更新方針

- 遊び方や調整値を変更したら、該当する現行ガイドを更新する。
- 機能の実装状況・優先順位は実装計画へ記録する。
- 過去の段階別記録は履歴として残し、新しい実装の説明で置き換えない。
- 検証結果には日付・対象・基準設定か調整後か・確認していない範囲を記載する。
- リンクはリポジトリ内の相対パスを使う。ログや作業用コピーはGitに含まれないため、閲覧に必須のリンク先にしない。
